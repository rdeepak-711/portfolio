# UI plan · 31 Oct 2026

Sources:
- the home page as built (`src/app/page.tsx` on portfolio-v2-dee);
- two passes on rahulm.me (31 Oct);
- the verified portfolio principles in the ui-ux-research skill (`references/portfolio.md`).

Most portfolio advice is practitioner opinion, not measured. Evidence labels are below.

## What's wrong now, ranked

1. **The home Writing section is stale.** It links 3 old items (the escalation-gate write-up and the two case studies) and none of the 6 posts written on 31 Oct. A recruiter on the home page never sees the new writing.
2. **There's no outside proof on the page.** The work that other people's repos can confirm sits inside project blurbs or nowhere:
   - hiring-agent issue #479 + fix PR #480;
   - crewAI #6072, where all 8 open PRs were run in Docker against a bug test.
3. **Email is a small link.** It's an ArrowLink in the hero and the contact section, the same weight as GitHub.
4. **No employer line in the first screen.** The hero says the role but not where he works or worked.
5. **The project list is long and uniform.** 4 large projects, 3 secondary cards and an Outbuiltit block, all in the same left-aligned shape. On a wide screen the screenshots sit below the text, so each project is a long scroll.
6. **Travel Measured has 2 posts but no project entry.**

## The plan, in build order

Each step is small, has its own test, and ships alone.

| # | Change | Fixes | Evidence | Cost |
|---|---|---|---|---|
| 1 | **Home Writing becomes a collection.** One row per lane with a count ("Outbuiltit · 5"); the open row lists its posts; the newest 3 posts are shown above. It's built from `NOTES` and `NOTE_LANES`, so it can't go stale again. A native `<details>`/`<summary>` works without JS and with the keyboard. | 1 | rahulm.me's collection (seen); principle 15, descriptive headings (opinion) | 45 min |
| 2 | **"Found in other people's code".** A short list, each entry with one plain line plus a link to the public issue, PR or comment. Each entry is verified by `gh` at build time. Open PRs say "open", never "fixed". Starts with #479/#480 and crewAI #6072. | 2 | rahulm.me's security-findings list (seen); principle 11, proof that's easy to verify (opinion) | 45 min |
| 3 | **Big email in Contact.** The address itself at display size, copyable, plus a Copy button. The footer repeats Email · Résumé. | 3 | principles 13–14, Comeau: "a working email link" (opinion) | 20 min |
| 4 | **Employer line under the hero headline.** "Software Engineer at Firestorm Internet since Jul 2025 · before that, UiPath". This must change when Firestorm ends. A test pins it to the experience data so they can't disagree. | 4 | principle 4, current role easy to spot (resume eye-tracking, by analogy) | 15 min |
| 5 | **Wide-screen project bands.** At ≥1024px each main project becomes text and screenshot side by side, alternating sides. Phone stays stacked as now. Same content, less scroll. | 5 | rahulm.me's zigzag (seen); principle 8, screenshot visible without a click (opinion) | 1 h |
| 6 | **Travel Measured as a secondary card.** One plain line, a link to the live site, and links to its 2 posts. No traffic numbers. | 6 | principle 6, a few relevant projects (opinion) | 20 min |

Total: about 3.5 h.

## Considered and not planned

- **Dee travelling down the page as you scroll** (rahulm's plane). Dee already has a fixed launcher bottom right and a pose per project, so a second moving Dee would compete with both. It also adds motion that has to be switched off for reduced-motion users. 1.5 h for the most distracting option on the list.
- **Serif italic accent words.** CLAUDE.md fixes the type system (Bricolage, Hanken, JetBrains Mono).
- **Experience as story cards.** The current rows already read as stories, so it's low value.
- **A photo.** Only if Deepak supplies one (`public/deepak.jpg`).

## Done means

- All existing tests pass, and each step adds its own test first.
- tsc and eslint are clean.
- No sideways scroll at 390 and 1280. The keyboard reaches every collection row and the Copy button.
- Screenshots at 390 and 1440 are reviewed before deploy.
